# 🐾 Пух & Мустак — сайт на груминг салон

Модерен, напълно адаптивен (responsive) сайт на български език за груминг салон
за кучета и котки, с **онлайн резервационна система**.

Чист HTML/CSS/JavaScript — без билд процес, без рамки, без зависимости.
Отваря се с двоен клик и работи навсякъде, включително на GitHub Pages.

## Какво има в сайта

| Секция | Какво включва |
|---|---|
| **Начална (Hero)** | Заглавие, УТП, бутон „Запази час“, показатели за доверие |
| **За салона** | Специалист, опит, сертификати, специализации по козина, оборудване |
| **Услуги и цени** | 6 услуги с превключване на цените по размер (малко/средно/голямо куче, котка) и времетраене |
| **Резултати** | Интерактивен плъзгач „преди/след“ + филтър по порода/козина |
| **Отзиви** | Карти със звезден рейтинг |
| **Резервация** | Календар със свободни дати → свободни часове → форма с валидация → потвърждение |
| **Клуб „Пухчо“** | Лоялна програма (5+1) с карта с печати |
| **Чести въпроси** | Акордеон с 6 въпроса |
| **Контакти** | Google Maps, телефон, имейл, соц. мрежи, работно време |
| **Допълнително** | Плаващи бутони WhatsApp и Viber, бутон „нагоре“, мобилно меню |

**Резервационната система** работи изцяло в браузъра:

- показва само реални работни дни (пн–пт 09–19, сб 10–16, неделя — почивен);
- за днешния ден скрива вече миналите часове (+1 час буфер);
- заетите часове са детерминирани, тоест остават еднакви при презареждане;
- запазените часове се пазят в `localStorage` и вече не се предлагат на друг;
- валидира българските мобилни номера, имейла и задължителните полета;
- показва модал с потвърждение и UI за имейл/SMS известяване.

> ⚠️ В демо режим резервацията се пази **само в браузъра на клиента**.
> За истински имейл/SMS виж [раздела по-долу](#как-да-получавам-резервациите-на-имейл).

## Преглед локално

Най-лесно: отвори `index.html` с двоен клик.

За да работят коректно всички ресурси, по-добре пусни малък локален сървър:

```bash
# Python (идва с macOS и Linux)
python3 -m http.server 8000

# или с Node.js
npx http-server -p 8000
```

След това отвори <http://localhost:8000>.

## 🚀 Качване на GitHub Pages

Сайтът е статичен, така че GitHub Pages го хоства **безплатно** и без настройки.
Ето трите варианта — избери **Вариант 1**, ако не си сигурен.

### Вариант 1 — публикуване от клон (най-лесно, без Actions)

1. Влез в репото си в GitHub: `https://github.com/DilyanNIliev/grooming-salon`
2. Отвори **Settings** (горното меню на репото) → в лявата колона **Pages**.
3. В полето **Source** избери **Deploy from a branch**.
4. В **Branch** избери клона, който да се публикува:
   - `main` — ако вече си слял промените, **или**
   - `claude/grooming-salon-website-imarem` — за да видиш сайта веднага, преди сливане.
5. За папка остави **`/ (root)`** и натисни **Save**.
6. Изчакай 1–2 минути и презареди страницата — най-горе ще се появи зелена кутия с адреса:

   ```
   https://dilyanniliev.github.io/grooming-salon/
   ```

Всеки следващ `git push` към този клон обновява сайта автоматично за ~1 минута.

### Вариант 2 — сливане в `main` първо (препоръчително за продукция)

```bash
git checkout main
git merge claude/grooming-salon-website-imarem
git push origin main
```

След това повтори стъпките от Вариант 1, но избери клон `main`.

### Вариант 3 — с GitHub Actions (ако искаш деплой само при промяна)

В **Settings → Pages → Source** избери **GitHub Actions**, после създай файл
`.github/workflows/pages.yml` със следното съдържание:

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: '.'
      - id: deployment
        uses: actions/deploy-pages@v4
```

### Собствен домейн (например `puhimustak.bg`)

1. В **Settings → Pages → Custom domain** въведи домейна и запази.
2. При регистратора на домейна добави DNS записи:
   - за `www.puhimustak.bg` → `CNAME` към `dilyanniliev.github.io`
   - за голия домейн `puhimustak.bg` → четири `A` записа към
     `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
3. Изчакай DNS-а (до 24 ч.) и включи **Enforce HTTPS**.

### Ако нещо не се вижда

| Проблем | Причина / решение |
|---|---|
| 404 при отваряне | Pages още не е билднал — изчакай 2 мин. и провери дали клонът е правилният |
| Сайтът е без стилове | Проверка: всички пътища са относителни (`assets/...`), без водеща наклонена черта `/` |
| Промените не се появяват | Кеш на браузъра — `Ctrl + F5` (или `Cmd + Shift + R`) |
| Липсват изображения | Файлът `.nojekyll` трябва да съществува в корена на репото |

## Как да редактирам съдържанието

**Текстове, телефон, адрес, отзиви, въпроси** → директно в `index.html`.
Потърси текста и го замени. Телефонът е на няколко места:

```
tel:+359881234567     ·     https://wa.me/359881234567     ·     viber://chat?number=%2B359881234567
```

**Услуги и цени** → в началото на `assets/js/script.js`, масивът `SERVICES`:

```js
{
  id: 'kapane',
  icon: '🛁',
  name: 'Къпане и сушене',
  desc: 'Топла баня с хипоалергенен шампоан…',
  price: { small: 25, medium: 35, large: 45, cat: 40 },   // лева
  time:  { small: '45 мин', medium: '60 мин', large: '80 мин', cat: '50 мин' }
}
```

**Работно време** → обектът `HOURS` в същия файл (`0` = неделя … `6` = събота):

```js
const HOURS = {
  1: [9, 19], 2: [9, 19], 3: [9, 19], 4: [9, 19], 5: [9, 19],
  6: [10, 16],            // събота
  0: null                 // неделя — почивен ден
};
```

**Цветове** → най-отгоре в `assets/css/style.css`:

```css
:root{
  --coral:#E8674C;        /* акцентен цвят */
  --coral-dark:#C4553D;   /* по-тъмен вариант — за текст и линкове */
  --mint:#79C3A8;
  --cream:#FFF8F3;
}
```

Ако смениш акцента, провери контраста на `--coral-dark` върху кремав фон —
трябва да е поне **4.5:1** (виж <https://webaim.org/resources/contrastchecker/>).

**Галерия „преди/след“** → масивът `GALLERY` в `script.js`. Всеки запис търси два
файла: `assets/img/<slug>-before.svg` и `assets/img/<slug>-after.svg`.

## Как да получавам резервациите на имейл

В `assets/js/script.js`, във функцията за изпращане на формата, има маркирано място:

```js
/* --- ТУК се свързва истински бекенд --- */
```

Избери един от вариантите:

### А) Formspree (най-бързо, без код на сървър)

1. Регистрирай се в <https://formspree.io> и създай форма — получаваш ID.
2. Замени коментара със:

```js
fetch('https://formspree.io/f/ТВОЯТ_ID', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', Accept: 'application/json' },
  body: JSON.stringify(booking)
});
```

### Б) Google Sheets + Apps Script (безплатно, резервациите влизат в таблица)

1. Създай Google Sheet → **Extensions → Apps Script**.
2. Постави скрипт, който записва `e.postData.contents` в нов ред.
3. **Deploy → New deployment → Web app**, достъп „Anyone“ — копирай URL-а.
4. Използвай го в `fetch(...)` с `mode: 'no-cors'`.

### В) EmailJS (имейл директно от браузъра) — <https://www.emailjs.com>

### SMS известия

GitHub Pages хоства само статични файлове, така че SMS-ите изискват външна услуга —
например [Twilio](https://www.twilio.com) или български доставчик (SMS.bg, iSMS),
извикана от малък сървър или от Apps Script от вариант Б.
Полето „Искам напомняне по SMS“ вече подава `booking.sms: true`.

## Как да сложа истински снимки

Илюстрациите са векторни SVG, за да няма външни зависимости и счупени линкове.
За да ги замениш със снимки на истински клиенти:

1. Сложи снимките в `assets/img/` (препоръчително **WebP**, ширина 800–1200 px).
   Оптимизирай ги на <https://squoosh.app> — целѝ под 150 KB на снимка.
2. Сменѝ разширенията в `index.html` (hero, екип, аватари), напр.:

   ```html
   <img src="assets/img/hero.webp" width="720" height="620"
        alt="Усмихнато подстригано куче след груминг" fetchpriority="high">
   ```

3. За галерията сменѝ разширението в `assets/js/script.js`:

   ```js
   src="assets/img/${g.slug}-before.webp"
   ```

4. **Задължително** попълни смислен `alt` текст на всяка снимка — това е важно
   и за SEO, и за хора, които ползват екранен четец.
5. Запази атрибутите `width` и `height` — те предотвратяват „подскачането“
   на страницата при зареждане (CLS).

Илюстрациите могат да се регенерират по всяко време с:

```bash
python3 tools/generate_assets.py
```

## SEO настройки преди пускане

В `<head>` на `index.html` замени `https://example.com/` с истинския адрес на сайта —
на три места: `<link rel="canonical">`, `og:url` и `og:image`.
Същото направи и в `sitemap.xml` и `robots.txt`.

Вече е налично:

- заглавия `h1` → `h2` → `h3` в правилна йерархия (само един `h1`);
- `meta description`, Open Graph и Twitter Card тагове;
- структурирани данни (JSON-LD, тип `PetGroomer`) — работно време, адрес, рейтинг,
  за да излиза салонът с богат резултат в Google;
- `lang="bg"` и семантични тагове (`header`, `main`, `section`, `footer`, `nav`).

За снимката при споделяне в социални мрежи е добре да сложиш **PNG/JPG 1200×630**
вместо SVG — Facebook не показва SVG. Отвори `assets/img/og-image.svg` в браузъра,
експортирай го като PNG и промени `og:image`.

## Достъпност и производителност

- Контраст на текста над **4.5:1** (основният текст е 11:1).
- Пълна навигация с клавиатура + видим фокус и „Прескочи към съдържанието“.
- Фокус-капан в модала и затваряне с `Esc`.
- `aria-label`, `aria-expanded`, `aria-live` за динамичните части.
- Уважава `prefers-reduced-motion` — анимациите спират при системна настройка.
- Без външни JS библиотеки; шрифтовете се зареждат с `display=swap` и имат
  системен резервен вариант, така че текстът се вижда веднага.
- Всички изображения под основния екран са с `loading="lazy"`.
